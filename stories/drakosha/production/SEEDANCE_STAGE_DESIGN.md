# Design: the "seedance" batch stage inside Drakosha_SceneFlow

Goal: EP1 scenes 2–4 video batch (jobs 10–19) runs ONLY through the studio's existing guarded boundary, with prompts EMITTED from typed shot records so an untagged character is unrepresentable. Extends `Drakosha_SceneFlow.res` (1301 lines; stages refs/storyboard/motion; one spawn point `Cinema_Backends.run`; receipts `frosya.generation-receipt/v1`; ≤2 attempts/subject; readiness re-verified inside the lease before spawn).

## 1. New typed data (in SceneFlow's implementation, private like the rest)
```rescript
type castToken = Frosya | Vasya | Mama | Papa | Babies | YagaFlight | YagaDomovoy
type propToken = Room | Roof | Door | Stupa | Top | Tin
type shotRecord = {
  jobId: string,            // "job12"
  shots: string,            // "SH024-027" — must match the shooting script
  cast: array<castToken>,   // full roster present in these shots
  props: array<propToken>,
  startImage: option<string>, // None = refs+text only (jobs 13, 14)
  durationSec: int,
  creative: string,         // the CINEDANCE choreography blocks ONLY:
                            // SCENE CONTEXT / LOCATION MAP / FORMAT MODE /
                            // OPTICS / CAMERA / ACTION TIMING / PHYSICS /
                            // LIGHTING / AUDIO — no character tag lines allowed here
}
```
Registry (also typed, one place): castToken → (@TAG line text, reference file path); propToken → reference path. The registry is where the canon lives: FROSYA maps to the PRE-GIFT cutout for this batch; PAPA maps to the deterministic Papa crop from the approved author packet; MAMA maps to `packet_pages/mama-06.png`; BABIES map to packet babies-13 with the "exactly two babies" language inside the emitted tag line. Frames extracted from generated video are never character-design references.

## 2. The emitter (kills the untagged-мама class by construction)
`emitPrompt(record)` = SCENE CONTEXT (from creative) + "ACTIVE REFERENCES" section GENERATED by mapping `record.cast` through the registry (each line: `@TAG: description. 100% matches the reference.`) + the remaining creative blocks + POSITIVE CONSTRAINTS generated from cast ("Exactly these characters: ...; no additional people; exactly two babies") . `emitArgs(record)` = `--start-image` (if Some) + `--image-references` for every cast+prop token via the SAME registry lookup. Prompt tags and bindings share one source; they cannot drift. A lint inside the emitter rejects any `creative` text containing an "@" tag or a character name not in `cast` (catches stale hand-written text).

## 3. Validation inside the boundary (front door, not checker-on-top)
Before spawn, per job: every registry file exists; `shots` range exists in the shooting script file; startImage exists if Some; duration ∈ {5,8,12}; estimated cost via `higgsfield generate cost` summed ≤ the allowance. Reuses SceneFlow's readiness/lease pattern: re-validate immediately before each spawn, receipts for every attempt (extend receipt schema with `shotRecordSha256`).

## 4. The wall (see WALL_RUNBOOK.md)
The stage's spawn point goes through `hfgate-submit` (HOME=/Users/hfgate/gate) instead of calling `higgsfield` with the agent's env. SceneFlow validates and emits; the gate re-validates the artifact hash, enforces the human-held allowance, runs serially, appends the ledger. Studio side compiles `Drakosha_GateSubmitCli.res.mjs` → installed by the human as /usr/local/bin/hfgate-submit (step 4 of the runbook).

## 5. Batch data for jobs 10–19
Source of truth for cast/props/start-images: production/preflight/cast_manifest.tsv (already script-derived, reviewed this session; job13/job14 startImage=None per the director's close-up ruling; kf13/kf14 keyframes retired). Creative blocks: port from rnd/seedance_test/skill_run2/job*.prompt.txt BUT strip their ACTIVE REFERENCES + character descriptions (those become emitted) and keep only choreography. Model: seedance_2_0 (style fidelity) unless the director rules otherwise after the 2.5 style-drift observation.
